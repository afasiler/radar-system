# 🛫 Flight Tracker Radar System

A highly scalable, real-time flight tracking and simulation system built with a microservices architecture. 

This project goes beyond a simple frontend-backend relationship by introducing a dedicated **Physics Simulation Engine** and **Spherical Linear Interpolation (SLERP)** for a buttery-smooth 60 FPS radar experience.

---

## 🏗️ System Architecture

The system is strictly decoupled into three main components:

### 1. The Database (Single Source of Truth)
- **PostgreSQL / PostGIS**
- Enforces strict data normalization.
- `flights` table: Stores static flight plans (Origin, Destination, Waypoints).
- `flight_positions` table: The "Black Box" storing high-frequency, second-by-second telemetry data generated by the simulator.

### 2. The Simulation Engine (Port 8001)
- **Python / FastAPI**
- A standalone worker that acts as the physics brain of the system.
- Reads static flight plans from the database and runs them through a localized event loop.
- Utilizes **Great Circle Math** to calculate actual spherical Earth routes.
- Generates realistic **VNAV (Vertical Navigation)** profiles (Takeoff climb, 36.000 ft Cruise, Landing descent).
- Broadcasts real-time position, altitude, and speed data to the backend via REST API.

### 3. The Radar Frontend (Port 5173)
- **React / Leaflet**
- Completely decoupled from the Simulator. It acts purely as an observer.
- Fetches database telemetry every 2 seconds via the backend.
- Applies **SLERP (Spherical Linear Interpolation)** to smooth the 2-second data gaps into seamless, 60 FPS real-time UI movement.

---

## 🚀 Key Features

* **Real-time SLERP Animation:** Planes move smoothly on the map without "teleporting" or stuttering between data fetches.
* **Offline Catch-Up (Crash Recovery):** If the simulator service drops, it automatically calculates the missed time-gap and bulk-inserts the missing history into the database upon reboot (Fast-Forward).
* **Live Weather Radar Integration:** Uses `RainViewer API` to overlay live global precipitation clouds gracefully.
* **Time Travel (Historical Data):** The UI slider allows users to rewind and view past flight data directly from the DB without interrupting the live backend simulator.
* **Graceful Degradation:** The UI and Simulator continue to function perfectly even if external APIs (like weather) go offline.

## 🛠️ Quick Start

The entire stack can be launched via a single orchestrated bash script.

1. Ensure **Docker Desktop** is running (for PostgreSQL).
2. Double-click the `start_all.command` file located in the root directory.

The script will automatically:
- Launch the Database via `docker-compose`
- Start the Main API Backend (`:8000`)
- Start the Simulation Engine (`:8001`)
- Start the React Radar UI (`:5173`)

### Ports & Access
- **Radar UI:** `http://localhost:5173`
- **Simulator Dashboard:** `http://localhost:8001/ui`
- **Backend API Docs:** `http://localhost:8000/docs`
